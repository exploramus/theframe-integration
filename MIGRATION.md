# Migration: DOCS.md → Integration

This guide removes the YAML from the original [DOCS.md](https://github.com/tilo-boehmann/theframe-controller/blob/main/DOCS.md) safely. The order matters: every block depends on others, and removing them in the wrong sequence causes Home Assistant to log errors and disable entities.

**Backup first.** Copy `configuration.yaml`, `automations.yaml`, `scripts.yaml`, and (if you have one) `homekit.yaml` somewhere safe before you start.

The integration must be installed and the add-on running v1.0.16+ before you remove anything.

---

## Step 0 — Verify the integration is healthy

Before deleting anything, confirm the new world works:

1. **Settings → Devices & Services** — the integration shows one device "The Frame", no errors.
2. Open **Developer Tools → States** and search `the_frame`. You should see:
   - `switch.the_frame_slideshow`
   - one `switch.the_frame_art_<keyword>` per keyword the add-on knows
   - `number.the_frame_slideshow_interval`
   - `select.the_frame_keyword`
   - `sensor.the_frame_current_image`, `image_count`
   - `binary_sensor.the_frame_in_art_mode`, `sync_pending`
   - `button.the_frame_sync_files`, `next_image`, `previous_image`
3. **Developer Tools → Services** — call `theframe.show_file` with a known `file_name` and confirm the TV switches.
4. **Media Browser → The Frame** — thumbnails render in *All images* and per-keyword folders.

If any of this fails, stop and fix the integration before removing the YAML — the YAML is your fallback.

---

## Step 1 — Disable the old automations (don't delete yet)

The five automations from DOCS.md are the active *consumers* of the helpers and template switches. Disabling them first means the rest of the cleanup cannot accidentally trigger a stale automation against an entity that no longer exists.

In **Settings → Automations & Scenes**, toggle these to *disabled* (slider on the right):

- The Frame Show
- Update Frame Keyword Dropdown
- TheFrame Update Slideshow Keywords from Selection
- TheFrame Update Slideshow Keywords
- TheFrame Interval HomeKit to Input Number
- TheFrame Interval Input Number to HomeKit

Now confirm the integration's slideshow toggle still advances images: turn `switch.the_frame_slideshow` on, set `number.the_frame_slideshow_interval` to 1, and watch the TV. The advance is driven by an internal 1-minute tick inside the integration ([__init__.py](custom_components/theframe/__init__.py)), so the time_pattern automation isn't needed.

---

## Step 2 — Update the HomeKit bridge

The HomeKit bridge in DOCS.md exposes the *old* entities (`input_select.theframe_interval_homekit`, the template switches, `input_boolean.the_frame_show`). Repoint it at the new ones.

If your HomeKit config lives in `configuration.yaml`:

```yaml
homekit:
  - filter:
      include_entities:
        - switch.the_frame_slideshow
        - number.the_frame_slideshow_interval
        - select.the_frame_keyword
        - switch.the_frame_art_natur
        - switch.the_frame_art_landschaft
        # ... one line per keyword switch you want in Apple Home
        - button.the_frame_next_image
        - button.the_frame_previous_image
        - button.the_frame_sync_files
```

Remove any `include_entities`/`include_domains` lines that reference the old `input_*`, `switch.frame_art_*` (template), or `automation.theframe_*` entities.

Restart HA, then re-pair the bridge in the Apple Home app (or remove and re-add the bridge if Apple Home stubbornly caches the old set). HomeKit IDs change when the bridge contents change — there is no clean rename.

---

## Step 3 — Remove the rest_command and shell_command blocks

Now that no automation calls them, these are safe to delete from `configuration.yaml`:

```yaml
rest_command:
  initialize_slideshow: ...
  show_slideshow_next: ...
  show_slideshow_previous: ...
  show_slideshow_index: ...
  sync_files: ...
```

**Keep `shell_command.image_sync`** if you still want HA to trigger the rclone OneDrive→local sync (the integration only does the local↔TV reconciliation, not the cloud step). If you remove it, replace it with one of:

- a manual cron on the host that runs `image_sync.sh`
- a HA shell_command kept just for that one script, called from a daily automation that then presses `button.the_frame_sync_files`
- the OneDrive integration in HA + a Folder Watcher

If you keep `shell_command.image_sync`, also keep the `script:` and `automation:` includes at the top of the file.

---

## Step 4 — Remove the template switches

Only after Step 2 (HomeKit no longer references them) and after confirming no Lovelace dashboard still binds to `switch.frame_art_*`, delete the entire block:

```yaml
template:
  - switch:
      - name: Art Architektur
        ...
      # all 17 of them
```

If `template:` only contained these switches, remove the whole `template:` key. Otherwise leave the key and just delete the affected list items.

The new switches generated by the integration are named `switch.the_frame_art_<slug>`. German umlauts are transliterated (`Blüte → bluete`), so they're readable rather than the diacritic-stripped form HA's default slugify would produce. Existing references to the old DOCS.md `switch.frame_art_*` IDs need to be updated to the new `switch.the_frame_art_*` form (one find-and-replace across your YAML/dashboards/HomeKit filter).

---

## Step 5 — Remove the REST sensor

Delete this from `configuration.yaml`:

```yaml
sensor:
  - platform: rest
    name: TheFrame Keywords
    resource: http://localhost:5000/available_keywords
    ...
  - platform: template
    sensors:
      theframe_keyword_list:
        ...
```

The integration polls `/available_keywords` itself (see [coordinator.py](custom_components/theframe/coordinator.py)).

---

## Step 6 — Remove the input helpers

Last to go, because everything else may have referenced them. Delete from `configuration.yaml`:

```yaml
input_select:
  theframe_interval_homekit: ...
  theframe_slideshow_keyword_select: ...   # if it lived here

input_text:
  theframe_slideshow_keywords: ...         # if it lived here

input_number:
  theframe_interval: ...                   # if it lived here
  theframe_slideshow_index: ...            # if it lived here

input_boolean:
  the_frame_show: ...                      # if it lived here
```

Some of these may live in the **UI helpers** (Settings → Devices & Services → Helpers) instead of YAML. Delete them there.

> **Note on `input_number.theframe_slideshow_index`** — the new add-on tracks the slideshow index internally, exposed via `sensor.the_frame_slideshow_position` (disabled by default). You only need this if you previously built UI around it; otherwise just delete the helper.

---

## Step 7 — Delete the disabled automations

With every dependency gone, delete the six automations you disabled in Step 1. Either via the UI (Settings → Automations & Scenes → ⋮ → Delete) or by removing them from `automations.yaml`.

---

## Step 8 — Final checks

```bash
# Inside HA: Developer Tools → YAML → Check Configuration
```

If it passes:

1. Restart HA one final time.
2. Watch `home-assistant.log` for warnings about missing entities — usually a Lovelace card or script still pointing at a deleted helper. Fix or delete the reference.
3. Open the dashboard and the Apple Home app. Everything you migrated should still work; nothing should be broken.

---

## Quick rollback

If something goes wrong mid-migration:

1. Restore the YAML files from your backup.
2. Re-enable the disabled automations (Step 1).
3. Restart HA. The old setup runs again.
4. The integration can stay installed in parallel — it doesn't conflict with the old YAML, it just duplicates state. Once you've fixed the issue, restart the migration from Step 1.

---

## What the integration intentionally does *not* replace

- **`image_sync.sh` (OneDrive → local)** — runs in the add-on, not in HA's process. See Step 3 above for options.
- **`theframe_dashboard.yaml`** — that's a Lovelace dashboard, not a backend object. Update it manually to use the new entity IDs (next iteration could ship a starter dashboard YAML).
- **HomeKit reload trigger** — the old `Update Frame Keyword Dropdown` automation called `homekit.reload` after rebuilding the dropdown. With dynamic switches you don't need this — new keyword switches appear at the next HA start, and the HomeKit bridge picks them up on its own reload cycle.
